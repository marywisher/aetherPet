## 1. 项目背景与核心目标

### 为什么做
旅行青蛙下架后，市场缺少一款「佛系陪伴」产品：低互动频率、无社交压力、有真实记忆的虚拟宠物陪伴。AI 时代使个人开发者可以用开源方式做出这样的产品。

### 核心目标
做一款**开源、可插拔、去中心化理念**的佛系陪伴应用 **AetherPet**：
- 核心体验：像旅行青蛙的「活人感 + 有记忆 + 无社交 + 随机触发 + 低频交互」
- 架构理念：核心基座 + 可插拔插件（Live2D、明信片、AI 对话等按需增减）
- 隐居模式：pet 之间默认不交互（隐居），数据归用户；未来支持多服务中心与数据迁移
- 开放核心 + 双许可证（核心基座开源，增值服务可商业化）

### 产品原则（防动摇清单）
1. **佛系纪律**：不追留存、不设置 KPI、不强制互动；用户倾注时间自然回来
2. **数据主权**：pet 的数据（记忆、时间线）属于用户，可导出、可迁移
3. **少打扰**：所有触达通道（公告、邮箱）低频、谨慎使用；pet 的主动触达遵守退避间隔
4. **表现与逻辑解耦**：事件引擎与素材包互不感知，风格可配置

### 面向用户的命名约定
- 「隐居」模式 = pet 各自过各自的，不与其他 pet 社交（对外不用「单机」等技术术语）
- 交互文案禁止使用「打卡」「签到」「任务」等暗示运营的语言

## 2. 目标用户

### 终端用户（轻陪伴人群）
- 20–40 岁，经历过旅行青蛙时代
- 想要「被惦记」而非「被消费注意力」的陪伴
- 单次使用时间约 1 分钟内、零连续互动要求

### 共创开发者（插件作者）
- 项目从第一天设计干净的插件契约与素材包规范
- 贡献门槛最低化：不写代码也能通过素材包定制表现层

## 3. 核心功能需求（MVP）

### 3.1 账号体系（无密码）
- **邮箱 + 邮箱验证码**注册/登录（无密码体系，参考 Magic Link 模式）
- 验证码：有效期 10 分钟；同邮箱 5 分钟内限发 3 次；IP 维度全局限流
- 登录成功发放 **30 天有效 token**，期间免验证码；提供「退出登录」入口
- **账号申诉机制**（MVP 提供人工兜底通道）：账号创建时可记录数据导出备份的 hash，申诉时以备份比对作为身份证明
- 一个账号下可有多个 pet（结构一对多；MVP 首发每账号 1 pet，创建账号即拥有第一只 pet，提供最小命名 UI；改名/删除 MVP 不做并在文档明确标注）

### 3.2 角色状态机
- pet 有状态：在家 / 出门散步 / 旅行中
- pet 有基础记忆：用户叫它什么、喜欢什么、收过哪些物品
- 「活人感」地基：pet 的行为有连续性与记忆引用

### 3.3 随机事件引擎（灵魂组件）
- 根据 pet 状态、记忆与流逝时间，低频随机产生事件
- 事件 = 结构（类型/参数） + 表现（素材包的文案/插画插槽），二者解耦
- 文案分两档：日常废话（高频）+ 偶尔诗意（约 1/10 概率）
- **记忆引用量化要求**（最低门槛）：
  - 事件文案 ≥30% 概率自然带出 pet 名字
  - 回信至少 1 条记忆引用（物品名 / 用户命名 / 时间锚点任一项）
  - 事件引用「几天前」「上周」类时间锚点表达
- **退避间隔**（pet 主动触达频率，见 CONTEXT.md 表）：用户缺席 ≥1 天 → 3 天间隔；≥3 天 → 7 天；≥7 天 → 30 天；更久维持 30 天上限

### 3.4 补算（catch-up simulation）
- **补算时机**：服务端在用户下次发起同步请求时执行（非进程重启、非前端打开）
- 单次补算**生成事件数 ≤ 20**；超出部分只生成**一条聚合摘要事件**（如「过去 30 天，Pet 出门走了 4 次、收过 2 片枯叶」）
- 超过 7 天离线：按「每天 1 条聚合」方式生成，避免堆积
- **补算期间 pet 状态机随时间推进**，状态转换与事件引擎耦合输出（出门事件 → 状态切到「出门」）
- 补算结果**渐进披露**：时间线首屏只显示「过去 X 天」入口卡片，点开才展开事件流
- 等效体验：pet 一直在过日子；结合退避间隔，长期不在的日子 pet 越来越安静

### 3.5 事件流（时间线）
- pet 产生事件的**单一时间轴**展示，回信也是普通事件类型之一
- 事件卡片带类型标签（散步/自言自语/回信…）；宠物单向输出、无回复按钮
- **记忆引用在事件卡片内用浅灰底色/角标高亮**
- 无社交压力：不引导互动、不提示「该来看看了」

### 3.6 档案页
- 查看 pet 当前状态、记忆片段、事件历史、收到过的物品（储物罐）
- 提供 pet 命名入口（创建时）

### 3.7 每日馈赠 + 回信（便当机制）
- 用户当天首次登录 → 系统从**物品池**随机奖励一件（进用户物品栏）
- 物品池：**最少 8 种**物品；抽取规则加权随机、排除最近 3 次重复；池空时兜底文案
- 用户主动将物品放桌上送给 pet（每天限一次，错过不惩罚，文案不用「签到/打卡」措辞）
- pet **回信**：次日或当晚（固定为「馈赠后 24 小时内随机生成」），信纸背景 + 回应文案，至少含 1 条记忆引用
- 回信不强制绑定馈赠：pet 也会自主冒信（「昨晚梦见你了」），间隔遵守退避表

### 3.8 公告
- 服务中心对使用者的低频触达通道（版本动态、大事记、迁移通知）
- 支持**已读/未读**、**静音（跳过 N 条）**、按时间倒序列表
- 空窗期回补的公告走聚合摘要策略（不逐一轰炸）

### 3.9 数据导出 / 导入（数据主权）
- 一键导出 pet 全部数据为 JSON，可导入恢复
- **导出规范 v1**：
  - 字段清单：pet 基础（名字/状态/创建时间）、记忆片段、事件时间线（结构+表现引用）、物品栏、储物罐、账号元数据（邮箱 hash/创建时间）
  - 排除项：会话 token、验证码记录、服务端临时元数据
  - 元信息：`schema_version: 1.0.0`、`exported_at`、`exported_from`（服务中心标识）、SHA256 校验和
- 导入失败分文案提示：版本号不匹配 / 校验和失败 / 字段缺失各自不同
- 导出前**确认弹窗**：明确提示包含/不包含的数据
- 多中心迁移为 v2 需求，但 schema 与版本号从 MVP 预留

### 3.10 表现素材包（可配置）
- 视觉 + 文案 = 素材包（theme/voice pack），不同服务中心可加载不同素材包，同一中心可切换
- 素材包内部目录规范 MVP 定死（`assets/theme-default/`），后续再公开为插件规范
- MVP 内置官方默认素材包（手绘暖调 + 废话/诗意文案）
- **素材包损坏/加载失败 → 回退默认素材包**兜底
- 可配置性验收：开发者模式下可加载另一套素材包并看到视觉/文案变化

### 3.11 事件-素材契约（插件生态起点）
- 需求文档定义 MVP 事件类型枚举与每种事件需要的素材/文案插槽：
  - 事件类型：外出散步、看水、数叶子、自言自语、带回物品、馈赠回信、自主冒信、聚合摘要、系统公告
  - 每个事件类型声明：所需文案插槽（标题/正文/落款）、可选插图插槽（信纸/场景图）、记忆引用位
- 契约先于开发定稿，插件与素材包都按契约对接

### 3.12 部署形态
- 官方托管中心可访问（别人打开就能用）；自托管有部署文档
- 性能冒烟纳入验收：页面加载 <3s（常规网络）、补算秒级完成

### 3.13 邮件推送（极端必要通道）
- 白名单限定：账号安全 / 系统故障 / 迁移通知 / 严重 bug 告知
- 每次推送留审计日志；频次一年内可控，遵循少打扰纪律

## 4. 明确不做（Out-of-scope，MVP 验收外）

- Live2D 表现插件
- AI 对话插件
- 手绘明信片/图片生成插件（AI 生图服务）
- 真实社交/联网互动（pet 之间、用户之间）
- P2P 组网、多服务中心联邦（协议层预留，不实现）
- 多 pet 切换 UI（结构预留，UI 不做）
- 插件市场
- 货币与市场购买（数据模型预留字段）
- pet 改名 / 删除（MVP 不做，文档明确）
- 备用登录方式（手机短信等；用户需保证邮箱可收信）

## 5. 非功能性需求

| 维度 | 要求 |
|------|------|
| 平台 | Web（跨平台视为不同外壳；MVP 仅 Web） |
| 性能 | 页面加载 < 3s（常规网络）；事件补算秒级内完成 |
| 可用性 | 移动端浏览器可浏览（响应式）；无需安装；30 天免登 |
| 数据 | SQLite（服务端）；全量导出 JSON（含 schema 版本 + 校验和） |
| 安全 | 邮箱验证码（10min 有效/节流）；30 天 token；账号申诉兜底；审计日志（验证码尝试/登录失败/导出导入） |
| 可配置 | 素材包可整体替换（表现层不硬编码在代码中） |

## 7. 发布前增量（pre-launch iteration）

> 来源：`docs/session-handoff-pre-launch.md`（决策已冻结）+ 本会话阶段 1 增量需求讨论（2026-09-14）。
> 目标：默认 pet 形象落地 + 克制级新手引导 + 发布前最小美化 + 差异化叙事定稿，赶在 12 月旅行青蛙停服前发布。

### 7.1 决策记录

**首开日跳过每日馈赠（P0-1 修复）**：创建 pet 当日不触发每日馈赠（`grantDailyItem` 跳过 `dailyGrantLastDate = null` 的当日发放），馈赠从 T+1 次日起正常执行。理由：首日本应无馈赠，pet 尚未出门活动；且初见字条 + 倒推小日子已构成首日欢迎仪式的完整叙事，馈赠卡会抢叙事焦点。次日馈赠时，每日欢迎卡文案 +「去送礼」按钮自然承担引导职责。此决策回归验收 10（每日馈赠闭环调整为首馈赠发生在 T+1）。

1. **默认 pet 形象 = 小刺猬**（默认素材包 `default` 的 pet 本体）
   - 自然系小物，与既有事件文案（看水/数叶子/蒲公英/枯叶/浆果）气质自洽；避开猫/狗赛道；不与旅行青蛙 IP 形象冲突
   - 同步：`CONTEXT.md` 术语表补一句；`docs/asset-prompts.md` 小刺猬 3 状态出图词（在家/出门/旅行中）
2. **差异化叙事（修正 handoff 草案）**
   - 主线：**开源 + 自托管 + 数据可迁移**；「你的 pet 与其记忆属于你，不属于任何一家厂商；即使官方停止运营，导出数据换个服务中心，它依然活着」
   - 借势钩子：「旅行青蛙停服后，你的蛙就没了。AetherPet 不会。」
   - 明示：AI 对话等能力按需作为插件接入（未来），不对外宣称「不喂给第三方」——不把聊天数据与 AI 能力对立
   - 发布目标 = 12 月旅行青蛙停服前；**不对标 Froggy Roams**（已看过其 Steam 首页，方向相去甚远）
3. **新手引导 = 克制级**（红线：无教程 UI、无步骤/任务/打卡字样；三处文案全部归素材包文本，引擎与 UI 不硬编码；与既有每日馈赠卡形成接力：首日 desktop hint 预习，T+1 馈赠卡上手操作指引）
   - ① `first_meeting` 初见事件：创建 pet 时仅触发 1 次；`ts = 创建时刻`（时间线为倒序 → 字条自动成为首页时间线第一条）；不进 `RANDOM_TYPES`、不进补算；FSM no-op；插槽 = 开场信文案 + 插图 key `first_meeting_note`
   - ② 桌面小字「可以把东西放桌上给我」= **placeholder 语义（常驻、空时显示）**：首页今日馈赠卡片缺席时显示 / `/gifts` 物品栏空态显示；有内容隐藏；**纯文字、不加链接**
   - ③ 首会话收尾句「下次回来的时候，{pet_name}会给你带礼物哦」：**双落点只亮一次**（首页页脚首会话 + 退出登录落地 `/login`）；localStorage 按 petId 标记；「礼物」语义 = 每日首次登录奖励 + 24h 内回信，不得暗示签到/打卡
4. **初始事件改造**（原阶段 2：1–3 条随机，可能含 outing）
   - 数量降为 **1–2 条**；限定**在 home 类型池**（watching_water / counting_leaves / self_talk / spontaneous_letter），保证 `at_home` 状态不变（初见场景「小刺猬已坐在桌上」不被破坏）
   - `ts` **倒推到创建时刻前 6~48 小时随机分布**（「它在你遇见它之前就住在这里」）；与字条（ts=创建时刻）构成「初见=最新、过去的小日子=更早」叙事
   - 实现：引擎增加「类型池覆盖」选项（不破坏现有随机逻辑），create 路由生成时使用
5. **素材包契约**：`first_meeting` 为第 12 类事件；pack_schema 升 **1.1.0**（minor，向后兼容）
   - `manifest.texts.first_meeting` **可选**（缺则该包渲染时回退 `default` 包同名文案）；`manifest.texts.guidance` 可选（desk_hint + first_session_farewell 两条）
   - 本期插图仅加 `first_meeting_note` 一个 asset key；通用「事件类型→插图」插槽留到 v2
   - 同步清单：类型枚举/生成器/注册表/素材包文本/回调函数契约表 docs/packs-contract.md §8.4 八项 + event-card `TYPE_LABELS` + manifest-schema + 契约-vs-schema 单测更新（11→12+2）
